# Frozen Unicode 3.2 SASLprep data

RFC 4013 uses RFC 3454's Unicode **3.2.0** character tables and normalization. The Adobe supplement requires this exact profile before truncating a revision-5 password to 127 UTF-8 bytes. The library's `Unicode32SaslprepData` is an immutable generated PHP object; production code does not load JSON, depend on ICU, or use the host's current Unicode version.

`unicode-3.2-saslprep.json` is the equivalent maintainer data, generated by `tools/build_saslprep_tables.py` from Python's documented `unicodedata.ucd_3_2_0` and `stringprep` tables. The generator preserves the historical normalization corrections by using the frozen database's `normalize('NFKD', ...)` results. `python tools/build_saslprep_tables.py --check` reproduces and compares both the JSON and PHP data.

Sources: [RFC 4013](https://www.rfc-editor.org/rfc/rfc4013), [RFC 3454](https://www.rfc-editor.org/rfc/rfc3454), [Python Unicode database documentation](https://docs.python.org/3/library/unicodedata.html), [Python stringprep documentation](https://docs.python.org/3/library/stringprep.html), and [Unicode's data licence](https://www.unicode.org/license.txt).

The derived Unicode data retain the [Unicode licence](UNICODE-LICENSE.txt). PHP implementation and test code remain under this project's MIT licence. `tools/validate_adobe_encryption.py` independently compares the SASLprep implementation with 13,572 deterministic Python cases covering normalization, Hangul, mappings, table boundaries, prohibitions, unassigned characters and BIDI.
