# Adobe PDF 1.7 ExtensionLevel 3 source catalogue

The retained source is [`adobe_supplement_iso32000.pdf`](../../adobe_supplement_iso32000.pdf), Adobe Acrobat SDK 9.0, edition 1.0, June 2008. Its original bytes and filename are preserved. `metadata.json` records the SHA-256 and document identity; every generated PHP definition references the exact physical PDF page, clause and source document.

This is an Adobe extension to PDF 1.7. Its table identifiers follow the PDF Reference numbering and are kept separate from the ISO 32000-1 catalogue. The supplement itself explains this distinction on pages 5–7.

`dictionaries.json` contains all **61 printed PDF dictionary tables**, **276 distinct printed entries**, and **six subtype specializations stated in prose** next to their tables. The six additional subtype definitions are labelled `prose specialization`: GEO and the five 3D measurement/comment types. The repeated `/MA` row on PDF page 57 is retained as two source occurrences and produces one entry. `classes.json` lists 61 dictionary classes, 61 immutable definition classes and 282 entry classes in `PDF\Specification\Adobe`.

An added-entry table explicitly composes the corresponding ISO base definitions and, where appropriate, other Adobe definitions. Unchanged inherited entries keep their ISO source. Changed entries keep their Adobe source. `corrections.json` records source ambiguities and implementation decisions without overwriting the printed source type, qualifier or description: these remain available through `source_constraints` and the original fields. Array-member types stated in prose are recorded as `validation_type`, separately from the printed `type` column.

The executable schemas check declared object types, explicit references, fixed names, unconditional required keys and the four RichMedia arrays requiring references to dictionaries. RichMedia command arguments accept only the source's strings, integers, reals, booleans or arrays of those scalar values; mixed scalar arrays are valid. Conditional rules, relationships across objects, geometry, ranges and application behavior keep their normative wording and remain explicit responsibilities of their corresponding mechanisms or callers.

`coverage.json` independently inventories all **66 Part I tables**: the 61 dictionary tables, four name/type lists and one XML attribute table. It also retains prose mechanisms, algorithms and all 207 implementation notes from Part II. These implementation notes describe Adobe product behavior; they are not automatically turned into universal PDF constraints. `references.json` records external resources referenced by the document.

Rebuild the source inventory with Python and `pypdf` / `pdfplumber`, then generate PHP classes:

```sh
python tools/extract_adobe_supplement.py
python tools/generate_adobe_supplement.py
```

Both tools support `--check`, which compares exact generated bytes without changing any files. The PHP generator reads only the committed JSON catalogue and uses Python's standard library; PDF extraction libraries are not PHP runtime dependencies. The independent coverage and external reference files are reviewed source inventories and are not overwritten by either generator.
