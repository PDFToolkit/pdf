# ISO/TS 32005:2023 structure namespaces

The retained source is `../iso32000-2-bundle/documents/ISO-TS-32005-2023-sponsored.pdf` (49 physical pages). Its exact hash is recorded in `inclusion.json` and the bundle catalogue. The PDF Association supplied this copy through its [sponsored standards programme](https://www.pdfa.org/sponsored-standards/).

`inclusion.json` preserves every printed child/parent occurrence from table 5 on physical pages 14–46: 53 rows, including `StructTreeRoot`. The generated `StructureInclusionTable` contains the same data without runtime file access. Run `python tools/generate_structure_inclusion.py --check` to verify the generated class and source identity. Re-extraction is explicit: `python tools/generate_structure_inclusion.py --extract` requires development-only `pdfplumber`.

`StructureNamespace`, `StructureRole`, `NamespaceRoleMap`, `NamespaceRoleMapping` and `StructureNamespaces` describe canonical document-local namespace objects. A bare role-map target means the default PDF 1.7 namespace; a namespaced target is an array containing the type and an indirect namespace reference (ISO 32000-2 table 356, physical page 744). Role resolution follows transitive mappings with cycle detection and an explicit operation budget. Shared roles in a mixed tree use PDF 2.0; the eleven unique PDF 1.7 roles remain in their original namespace. The standalone PDF 1.7 exemption is preserved.

`StructureInclusionRules` applies the table to resolved roles, including occurrence bounds, transparent Part/Div/NonStruct ancestry, grouping-only edges and Ruby/Warichu ordering. The native writer checks namespace membership, cross-document Ref associations and PDF 2.0 minimum versions. `NamespaceGraphValidation` also checks generic dictionary escape hatches against the actual frozen revision graph.

The default `Published2023` mode retains the source text. Its WP/Figure cell contains an undefined `c`. The explicit `Resolved336And440` correction selection applies the PDF Association resolutions for [Code/Sub, issue 336](https://github.com/pdf-association/pdf-issues/issues/336) and [WP/Figure, issue 440](https://github.com/pdf-association/pdf-issues/issues/440). This selection is not presented as a new ISO edition. Later discussions about Part/Div/NonStruct, grouping classification and Reference/Link are not silently incorporated.

`examples/pdf20-tagged-namespaces.php` demonstrates mixed standard namespaces, a custom mapped paragraph, canonical ParentTree entries, structural references and explicit metadata declarations. `tools/validate_pdf20_tagging.py` checks the generated bytes independently with pypdf, qpdf and optionally Poppler; it also compares shown glyph metrics against the actual embedded TrueType program. These checks do not certify semantic correctness or complete WTPDF/PDF-UA compliance. See the [WTPDF coverage record](../wtpdf-1.0/coverage.json).
