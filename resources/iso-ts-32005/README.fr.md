# Espaces de noms de structure ISO/TS 32005:2023

La source conservée est `../reference-documents/ISO-TS-32005-2023-sponsored.pdf` (49 pages physiques). Son empreinte exacte figure dans `inclusion.json` et dans le catalogue du bundle. Cette copie provient du [programme de normes sponsorisées de la PDF Association](https://www.pdfa.org/sponsored-standards/).

`inclusion.json` conserve toutes les occurrences enfants/parents imprimées dans le tableau 5 des pages physiques 14–46 : 53 lignes, dont `StructTreeRoot`. La classe générée `StructureInclusionTable` contient les mêmes données sans lecture de fichier à l’exécution. `python tools/generate_structure_inclusion.py --check` vérifie sa reproductibilité et l’identité de la source. La réextraction reste explicite : `python tools/generate_structure_inclusion.py --extract` demande uniquement la dépendance de développement `pdfplumber`.

`StructureNamespace`, `StructureRole`, `NamespaceRoleMap`, `NamespaceRoleMapping` et `StructureNamespaces` représentent des objets de namespace canoniques, propres au document. Une cible de mapping réduite à un nom désigne le namespace PDF 1.7 par défaut ; une cible qualifiée contient le type et une référence indirecte vers son namespace (ISO 32000-2, tableau 356, page physique 744). La résolution suit les mappings transitifs avec détection des cycles et limite explicite. Les types communs d’un arbre mixte utilisent PDF 2.0 ; les onze types propres à PDF 1.7 conservent leur namespace. L’exception prévue pour un arbre exclusivement PDF 1.7 est préservée.

`StructureInclusionRules` applique les relations aux rôles résolus : bornes d’occurrence, héritage transparent de Part/Div/NonStruct, relations réservées aux usages de regroupement, ordre Ruby/Warichu. Le writer vérifie l’appartenance des namespaces, les références Ref entre éléments d’un même document et la version minimale PDF 2.0. `NamespaceGraphValidation` contrôle également les dictionnaires génériques à partir du graphe figé de la révision effective.

Le mode `Published2023` par défaut conserve le texte fourni. Sa cellule WP/Figure contient un `c` non défini. La sélection explicite `Resolved336And440` applique les résolutions de la PDF Association pour [Code/Sub, ticket 336](https://github.com/pdf-association/pdf-issues/issues/336) et [WP/Figure, ticket 440](https://github.com/pdf-association/pdf-issues/issues/440). Cette sélection ne prétend pas constituer une nouvelle édition ISO. Les discussions ultérieures sur Part/Div/NonStruct, les catégories de regroupement et Reference/Link ne sont pas intégrées implicitement.

`examples/pdf20-tagged-namespaces.php` illustre des namespaces standards mixtes, un paragraphe personnalisé mappé, les entrées ParentTree canoniques, les références structurelles et les déclarations explicites de métadonnées. `tools/validate_pdf20_tagging.py` vérifie les octets indépendamment avec pypdf, qpdf et, facultativement, Poppler ; il compare aussi les métriques des glyphes montrés au programme TrueType réellement incorporé. Ces contrôles ne certifient ni la justesse sémantique ni une conformité WTPDF/PDF-UA complète. Voir le [relevé de couverture WTPDF](../wtpdf-1.0/coverage.json).
